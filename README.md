## Правила игры

Компьютер загадывает случайное существительное из 5 букв. У игрока есть **6 попыток**. После каждой введённой попытки компьютер выдаёт подсказку из 5 символов:

- `+` — буква есть в слове и стоит на правильной позиции;
- `^` — буква есть в слове, но стоит на другой позиции;
- `-` — такой буквы в слове нет (либо её "лимит" уже исчерпан, см. ниже).

Если ввести **пустую строку** (просто нажать Enter), компьютер сам подберёт и введёт наиболее подходящее слово-подсказку, основываясь на всей информации, накопленной за предыдущие ходы. Играя одними подсказками, можно наблюдать, как компьютер сам проходит игру от начала до конца.

Игра заканчивается победой (введено загаданное слово) или поражением (закончились попытки). В конце всегда выводится загаданное слово.

## Архитектура проекта

Проект разбит на 4 класса с чётким разделением ответственности — принцип, который последовательно соблюдается по всему коду:

```
Wordle (main)              — консоль, лог-файл, "дирижёр" всей программы
    │
    ├── WordleDictionaryLoader   — читает файл словаря, ничего больше
    │        │
    │        ▼
    ├── WordleDictionary         — хранит и нормализует слова
    │        │
    │        ▼
    └── WordleGame               — состояние партии + вся игровая логика
```

**Важное архитектурное правило:** только `Wordle.main` работает с консолью (`System.out`, `Scanner`) и с лог-файлом. Остальные три класса ничего не печатают и не читают файлы напрямую (кроме `WordleDictionaryLoader`, чья единственная задача — файлы). Это осознанное решение сделано специально для того, чтобы `WordleDictionary` и `WordleGame` можно было полноценно покрыть юнит-тестами без эмуляции консоли.

## Классы и их ответственность

### `WordleDictionaryLoader`

Единственная задача — прочитать файл словаря и вернуть список "сырых" строк.

```java
public List<String> loadWords(String path) throws IOException
```

- Использует `BufferedReader` поверх `FileReader` с явной кодировкой UTF-8.
- Обёрнут в `try-with-resources`, чтобы поток гарантированно закрылся.
- **Не занимается** ни фильтрацией, ни нормализацией слов — это сознательно вынесено в `WordleDictionary`.
- Если файла нет — пробрасывает `IOException` наружу как есть (это системная, а не игровая ошибка).
- Пустой файл — не ошибка на этом уровне, просто вернётся пустой список.

### `WordleDictionary`

Хранит **финальный, уже готовый к игре** список 5-буквенных нормализованных слов.

| Метод | Что делает |
|---|---|
| `WordleDictionary(List<String> words)` | Конструктор. Проходит по всем словам, для каждого: `trim()` → проверка длины (ровно 5) → если подходит, `toLowerCase()` + замена `ё→е` → добавление в список. |
| `static String normalize(String word)` | Приводит одно слово к игровому виду: `trim().toLowerCase().replace("ё", "е")`. Переиспользуется в конструкторе, в `containsWord()` и в `WordleGame`. |
| `String getRandomWord()` | Возвращает случайное слово из словаря (`Random.nextInt(words.size())`). |
| `boolean containsWord(String word)` | Проверяет, есть ли слово в словаре. **Сама нормализует** переданный параметр перед проверкой — вызывающему коду не нужно заботиться о регистре/пробелах. |
| `boolean isEmpty()` | Пуст ли словарь (используется при старте игры для проверки на `EmptyDictionaryException`). |
| `List<String> getWords()` | Возвращает **неизменяемую копию** (`List.copyOf`) внутреннего списка — чтобы никто извне не мог случайно испортить состояние словаря. |

### `WordleGame`

Хранит состояние одной партии и всю игровую логику: сравнение слов, обработку хода, накопление информации для подсказок.

**Поля:**
- `answer` (`final`) — загаданное слово.
- `steps` — оставшиеся попытки (стартует с `MAX_STEPS = 6`).
- `dictionary` (`final`) — ссылка на словарь.
- `lastGuess` — последнее введённое (нормализованное) слово, нужно для `isWon()`.
- `excludedLetters` (`Set<Character>`) — буквы, которых точно нет в слове (или чей "лимит" исчерпан).
- `exactPositions` (`Map<Integer, Character>`) — "позиция → точная буква на ней".
- `wrongPositions` (`Map<Character, Set<Integer>>`) — "буква → множество позиций, где она есть, но быть не должна".
- `usedWords` (`Set<String>`) — все уже введённые слова, чтобы подсказка не повторялась.

**Конструкторы:**
```java
public WordleGame(WordleDictionary dictionary)                  // обычная игра, случайный answer
public WordleGame(WordleDictionary dictionary, String answer)   // явный answer — используется в тестах
```
Первый делегирует второму через `this(dictionary, dictionary.getRandomWord())` — паттерн "конструктор-делегат", чтобы не дублировать инициализацию полей.

**Методы:**

| Метод | Что делает |
|---|---|
| `String checkGuess(String word)` | Чистый алгоритм сравнения `word` с `answer`, возвращает строку из `+`/`-`/`^`. Подробности — см. раздел ниже. |
| `String makeGuess(String word) throws WordNotFoundInDictionary` | "Обёртка" вокруг хода: проверяет слово через `dictionary.containsWord()`, если не найдено — бросает исключение **без списания попытки**. Если найдено — списывает попытку, нормализует слово, вызывает `checkGuess`, обновляет `lastGuess`, вызывает `updateConstraints`, запоминает слово в `usedWords`. |
| `boolean isWon()` | `answer.equals(lastGuess)`. Специально написано в таком порядке (не `lastGuess.equals(answer)`), чтобы не упасть с `NullPointerException`, если ходов ещё не было (`lastGuess == null`). |
| `int getSteps()` | Геттер оставшихся попыток. |
| `String getAnswer()` | Геттер загаданного слова (для финального вывода в конце игры). |
| `void updateConstraints(String word, String result)` | После каждого хода разбирает результат посимвольно и обновляет три структуры ограничений. Подробности — в разделе про подсказки. |
| `String suggestWord()` | Подбирает слово-подсказку на основе всех накопленных ограничений. Подробности — ниже. |

## Алгоритм сравнения слов (+/-/^)

Это центральная и самая нетривиальная часть задания — корректная обработка **повторяющихся букв**.

### Наивный подход не работает

Если сравнивать буквы независимо друг от друга, слова с повторами дают неверный результат. Например: `answer = "манго"`, `word = "нанос"`. Буква `н` в `нанос` встречается дважды (позиции 0 и 2), а в `манго` — только один раз (позиция 2). Раз позиция 2 уже даёт точное совпадение (`+`), для буквы `н` на позиции 0 свободных "копий" в ответе не осталось — она должна получить `-`, а не `^`.

### Решение — двухпроходный алгоритм

**Проход 1.** Идём по обеим строкам одновременно, посимвольно. Где буквы совпадают — ставим `+`. Буквы `answer`, которые **не** попали в `+`, складываем в `HashMap<Character, Integer>` — это "резерв" оставшихся букв ответа.

**Проход 2.** Для всех позиций, не отмеченных `+`, проверяем: есть ли буква слова игрока в резерве (счётчик > 0)? Если да — ставим `^` и **уменьшаем** счётчик (буква "потрачена"). Если нет — `-`.

Пример разбора: `answer = "манго"`, `word = "нанос"` → результат `"-++^-"`.

```java
public String checkGuess(String word) {
    char[] result = new char[5];
    Map<Character, Integer> availableLetters = new HashMap<>();

    // Проход 1: точные совпадения
    for (int i = 0; i < word.length(); i++) {
        char currentAnswer = this.answer.charAt(i);
        char currentWord = word.charAt(i);
        if (currentAnswer == currentWord) {
            result[i] = '+';
        } else {
            availableLetters.put(currentAnswer, availableLetters.getOrDefault(currentAnswer, 0) + 1);
        }
    }

    // Проход 2: частичные совпадения и промахи
    for (int i = 0; i < word.length(); i++) {
        if (result[i] == '\u0000') { // позиция ещё не заполнена
            char currentWord = word.charAt(i);
            if (availableLetters.getOrDefault(currentWord, 0) > 0) {
                result[i] = '^';
                availableLetters.put(currentWord, availableLetters.get(currentWord) - 1);
            } else {
                result[i] = '-';
            }
        }
    }
    return new String(result);
}
```

`'\u0000'` — значение массива `char[]` по умолчанию (null-символ), используется как маркер "ячейка ещё не заполнена".

## Система подсказок

### Три структуры ограничений

После каждого успешного хода `updateConstraints(word, result)` разбирает результат посимвольно и раскладывает информацию по трём структурам:

- `+` → `exactPositions.put(позиция, буква)`
- `^` → `wrongPositions.computeIfAbsent(буква, k -> new HashSet<>()).add(позиция)`
- `-` → буква добавляется в `excludedLetters`, **но только если эта же буква нигде больше в этом же слове не дала `+` или `^`** (см. раздел про баги ниже — это принципиальный момент).

### Три последовательных фильтра в `suggestWord()`

1. **Отсеять исключённые буквы.** Убрать из словаря все слова, содержащие хотя бы одну букву из `excludedLetters`, а заодно исключить уже введённые ранее слова (`usedWords`).
2. **Проверить "плавающие" буквы.** Для каждой буквы из `wrongPositions` слово-кандидат должно: (а) содержать эту букву хоть где-то, и (б) ни на одной из "запрещённых" для неё позиций.
3. **Проверить точные позиции.** Для каждой записи из `exactPositions` слово-кандидат должно иметь именно нужную букву именно на этой позиции.

Из финального списка кандидатов случайным образом выбирается одно слово. Если после всех трёх фильтров список пуст — это сигнал внутренней ошибки логики (по правилам ТЗ такого быть не должно), бросается `RuntimeException` с понятным сообщением.

**Важно:** алгоритм подсказки не "умный" — он не пытается выбрать наиболее информативное слово для максимального сужения круга кандидатов, а просто берёт случайное подходящее. Поэтому не гарантируется победа за минимальное число ходов (хотя обычно 4–6 ходов достаточно).

## Исключения

Исключения разделены на **игровые** (checked, ожидаемая часть нормального игрового процесса) и **системные** (unchecked, сигнализируют о том, что программа не может нормально стартовать):

| Класс | Родитель | Когда бросается | Где обрабатывается |
|---|---|---|---|
| `WordNotFoundInDictionary` | `Exception` (checked) | Игрок ввёл слово, которого нет в словаре | В игровом цикле `Wordle.main` — ловится точечно, выводится сообщение в консоль, ход не засчитывается |
| `EmptyDictionaryException` | `RuntimeException` (unchecked) | Словарь после загрузки и фильтрации оказался пустым | Общий `catch (Exception e)` в `main`, сообщение пишется в лог |

`WordNotFoundInDictionary` сделан checked специально — это заставляет явно объявлять `throws` в сигнатуре `makeGuess()` и не забыть обработать эту ситуацию. `EmptyDictionaryException` сделан unchecked, потому что это разовая проверка при старте, не требующая точечной обработки в разных местах кода.

## Обработка ошибок и логирование

`Wordle.main` использует **два вложенных `try`**:

```java
try (PrintWriter log = new PrintWriter(
        new OutputStreamWriter(new FileOutputStream("wordle.log"), StandardCharsets.UTF_8))) {

    try {
        // вся основная логика: загрузка словаря, создание игры, игровой цикл
    } catch (Exception e) {
        log.println("Критическая ошибка: " + e.getMessage());
    }

} catch (IOException e) {
    System.out.println("Не удалось создать лог-файл: " + e.getMessage());
}
```

- **Внешний `try-with-resources`** — гарантирует закрытие `PrintWriter` в любом случае.
- **Внутренний `try-catch`** — единая точка перехвата всех непредвиденных ошибок (файл словаря не найден, пустой словарь и т.д.). Пишет их в лог-файл, а не в консоль, чтобы не отвлекать игрока техническими деталями.
- **Внешний `catch (IOException e)`** — единственный случай, когда сообщение об ошибке всё же идёт в консоль: если не получилось создать сам лог-файл, писать об этом больше некуда.

Игровые ошибки (`WordNotFoundInDictionary`) ловятся **отдельно, внутри `while`-цикла**, а не во внешнем `catch` — иначе одна невалидная попытка ввода прерывала бы всю партию.

## Юнит-тесты

Тесты написаны для трёх содержательных классов и исключений; `Wordle.main` намеренно не тестируется юнит-тестами (см. пояснение ниже).

- **`WordleDictionaryTest`** — конструктор (нормализация + фильтрация на комплексном примере), три отдельных теста на `normalize()` (пробелы / регистр / замена `ё`), `getRandomWord()` (проверка через `containsWord()`, так как результат случайный), три теста на `containsWord()` (точное слово, "грязный" ввод, отсутствующее слово).
- **`WordleGameTest`** — несколько сценариев `checkGuess()` (точное совпадение, полное несовпадение, повтор буквы в слове игрока, повтор буквы в ответе), `makeGuess()` (успешный ход списывает попытку; невалидное слово бросает исключение и **не** списывает попытку), `isWon()` (`false` до первого хода, `true` после верного), а также специальный тест на баг с "лишней" копией буквы и тест на то, что подсказка не повторяет уже введённые слова.
- **`WordleDictionaryLoaderTest`** — с использованием `@TempDir` создаётся временный файл на диске: обычное чтение, пустой файл, несуществующий файл (ожидается `IOException`).
- **`WordleExceptionsTest`** — проверка, что оба кастомных исключения корректно сохраняют переданное сообщение.

Для тестов `WordleGame` добавлен отдельный конструктор `WordleGame(dictionary, answer)`, принимающий заранее известное слово-ответ — иначе тесты не могли бы предсказуемо проверять `checkGuess()`, так как обычный конструктор выбирает `answer` случайно.

**Почему `Wordle` (main) не покрыт тестами:** он работает напрямую с `System.in`/`System.out`/файлами, а вся содержательная логика сознательно вынесена в `WordleDictionary` и `WordleGame` именно для того, чтобы её можно было тестировать. Сам `main` — тонкий "координатор", проверенный вручную.

## Известные особенности и найденные баги

В процессе разработки было найдено и исправлено два содержательных бага, оба связаны с повторяющимися буквами:

### Баг 1 — лишняя буква ошибочно исключалась целиком

Если слово содержит одну и ту же букву дважды, и одна копия даёт `+`/`^`, а другая (из-за исчерпанного "лимита") — `-`, наивная реализация `updateConstraints` добавляла такую букву в `excludedLetters` **целиком**. Это приводило к тому, что правильный ответ (который как раз содержит эту букву) отфильтровывался из будущих подсказок, и в какой-то момент `suggestWord()` не находил ни одного кандидата.

**Пример:** `answer = "сахар"`, `word = "такса"` → результат `"+--^+"`. Буква `а` встречается на позиции 1 (`-`) и позиции 4 (`+`). Без исправления `а` ошибочно попадала в `excludedLetters`.

**Исправление:** добавлена проверка `letterHasMatchElsewhere(word, result, letter)` — перед тем как добавить букву с результатом `-` в `excludedLetters`, метод проверяет, не встречается ли та же буква где-то ещё в этом же слове с результатом, отличным от `-`. Если встречается — букву в "чёрный список" не добавляем.

### Баг 2 — подсказка могла повторять уже введённые слова

`suggestWord()` изначально не учитывал историю уже введённых слов, поэтому теоретически мог предложить то же самое (заведомо неверное) слово повторно.

**Исправление:** добавлено поле `usedWords` (`Set<String>`), в которое `makeGuess()` добавляет каждое успешно проверенное слово. Первый фильтр в `suggestWord()` сразу пропускает кандидатов, уже присутствующих в этом сете.

### Особенность, а не баг: подсказка не всегда оптимальна

Алгоритм подсказки берёт **случайное** слово из отфильтрованных кандидатов, а не то, что максимально сузит пространство вариантов. Из-за этого возможны партии, где несколько раз подряд предлагаются похожие слова (например, из семейства "-ашка": кашка/сошка/нычка/кишка), прежде чем находится верный ответ. Это соответствует ТЗ (там сказано "в идеале", а не "обязательно") и не является ошибкой — просто более простая эвристика, чем могла бы быть.

## Как запустить

1. Открыть проект в IntelliJ IDEA.
2. Убедиться, что файл словаря (`words_ru.txt`) лежит в корне проекта — программа запускается из этой директории, и путь к файлу передаётся как относительный.
3. Запустить `main()` в классе `Wordle`.
4. Вводить пятибуквенные слова в консоли, либо нажимать Enter для автоматической подсказки.
5. После завершения партии в файле `wordle.log` (тоже в корне проекта) можно проверить, не возникало ли системных ошибок во время сессии — при штатной игре файл должен остаться пустым.

Для запуска тестов — через встроенный раннер JUnit 5 в IntelliJ (зелёный треугольник рядом с классом или методом теста).
